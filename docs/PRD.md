# 个人博客 MVP 产品方案

状态：产品范围已确认，技术选型未开始
最后更新：2026-11-21

## 1. 定位

跑在自己电脑上的私人写作与整理工具。打开浏览器就能写，内容只属于自己，断网也能用。

产品性质是**本地私人写作台**，不是对外发布的博客。核心价值是积累与回看，不是传播。

| 维度 | 结论 |
|---|---|
| 读者 | 只有作者本人 |
| 写作设备 | 仅本机电脑，不做手机写作 |
| 访问范围 | 仅本机，局域网与公网均不可达 |
| 鉴权 | 不需要 |
| 域名 | 不需要 |
| 网络依赖 | 无，离线全功能可用 |

## 2. 已确认的决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 写作方式 | 浏览器内写作 | 作者明确要求，排除静态生成 + Git 发布路线 |
| 部署位置 | 本地电脑 | 暂不公开，无需托管服务 |
| 手机写作 | 不做 | 开放局域网访问会重新引入鉴权需求，与「不登录」冲突 |
| 内容形态 | 流程图 / 架构图 + 生活随笔 | 决定编辑器重心是图表与图片，而非代码高亮 |
| 数学公式 | 不做 | 内容方向不涉及 |
| 备份方式 | 导出 Markdown + git | 白送版本历史，且可异地容灾 |
| 仓库布局 | 代码与内容分仓 | 从结构上杜绝私密内容误提交到公开仓库 |

## 3. 用户与核心场景

只有一个用户：作者本人。

1. **开机即写**：一条命令启动服务，浏览器打开固定地址，两次点击内写下第一个字。
2. **碎片成稿**：新建草稿 → 写几段 → 自动保存 → 关掉；下次打开继续。
3. **图文混排**：粘贴截图、插入 Mermaid 图表，预览确认后标记完成。
4. **事后修正**：打开已完成文章 → 修改 → 更新，URL 保持不变。
5. **回看检索**：文章积累后按标签或关键词找回旧文。
6. **离线写作**：无网络环境下全部功能照常可用。

## 4. 功能范围

### 4.1 P0（MVP 必须）

| 功能 | 说明 |
|---|---|
| 一键启动 | 单条命令起服务，地址固定。启动摩擦决定使用频率 |
| 文章列表 | 草稿 / 已完成分栏 |
| Markdown 编辑器 | 浏览器内编辑 |
| 实时预览 | 编辑区与渲染结果同步 |
| Mermaid 图表渲染 | 预览与详情页均需支持，图表自适应容器宽度 |
| 图片粘贴 / 拖拽上传 | 图文内容的硬需求 |
| 草稿自动保存 | 防止丢稿 |
| 标记完成 / 撤回草稿 | 两态切换，见 5.2 |
| 编辑已完成文章 | URL 不变 |
| 文章详情页 | 图片、图表、目录 |
| 标签 | 整理与回看 |
| 本地数据持久化 | 文章与图片存本地文件，重启不丢 |
| 仅本机可访问 | 隐私边界 |
| 导出 Markdown | 备份入口，见第 7 节 |

### 4.2 P1（MVP 之后紧接着做）

| 功能 | 说明 |
|---|---|
| 全文搜索 | **私有场景下优先级最高的 P1**。文章攒到数十篇后，「以前写过的东西在哪」会成为最高频痛点 |
| 归档页 | 按时间回看 |
| 深色模式 | Mermaid 配色需随主题切换，避免黑底黑线 |
| 代码块语法高亮 | 基础 Markdown 代码块 P0 已支持，高亮主题延后 |
| 自定义站点标题 | 品牌感 |

### 4.3 明确不做

登录 / 注册 / 会话、域名、RSS、评论、阅读量统计、SEO 与分享预览、多用户、定时发布、邮件订阅、数学公式、手机写作、双向同步。

RSS 与 SEO 在只有作者一个读者时没有意义。

## 5. 信息架构与内容模型

### 5.1 页面结构

没有鉴权，整站皆私有，**不区分公开区与后台**：

```
/              首页 · 文章列表（草稿与已完成）
/posts/:slug   文章详情
/tags/:tag     标签聚合
/new           新建文章
/edit/:id      编辑文章
```

### 5.2 内容模型

```
文章 = 标题 + 正文(Markdown) + 标签[] + 状态 + 完成时间 + URL slug

状态：草稿 ⇄ 已完成
```

草稿与已完成是**同一篇文章的两个状态**，不是两种实体。这样「撤回」「再编辑」「改完重新标记完成」都是天然操作，无需转换逻辑。

「完成」在本地私有场景下不是对外发布动作，只是作者给自己设定的完结界定，同时为将来可能公开预留路径。

### 5.3 写作闭环

```
  新建 ──→ 编辑 ──→ 预览 ──→ 标记完成 ──→ 本地可读
            ↑  │                          │
            │  └─ 自动保存                 │
            └────────── 撤回 ←────────────┘
```

## 6. 优先级判断依据

公开博客里搜索是给读者的，MVP 可以不做。私有写作台里**搜索是给作者自己的**，因此标签、归档、检索的优先级整体上升，读者侧功能整体下降。

这是本方案与常规博客 MVP 最大的差异。

## 7. 备份与仓库布局

### 7.1 分仓

```
reader（public）    只放代码，数据目录排除在版本控制之外
content（private）  放导出的 Markdown 与图片
```

代码与内容生命周期不同：代码将来可能公开分享，内容始终私密。分仓后「误提交」这条路径从结构上不存在，比依赖忽略规则兜底可靠。

### 7.2 导出规则

- **单向快照，不做双向同步**。导出文件用于存档与容灾，修改导出文件不会回灌进系统。双向同步会引入冲突解决，不在 MVP 范围。
- 图片以**相对路径**引用同目录下的图片文件夹，导出包自洽，拷到任何位置均可离线阅读。
- 导出包推送到私有仓库后，GitHub 原生渲染 Mermaid，网页上可直接阅读图文 —— 相当于一份异地可浏览的备份，而非冷存档。

### 7.3 风险

本地方案唯一的真实风险是硬盘损坏。备份不是可选项，v0.1 就应养成导出习惯。

## 8. 验收标准

- 一条命令启动，浏览器打开固定地址即可写作
- 从打开到写下第一个字 ≤ 2 次点击
- 断网状态下全部功能可用
- 关闭服务、重启电脑后，文章与图片完整无丢失
- 整站数据可一次复制完成备份
- 粘贴图片到插入正文 ≤ 2 步
- Mermaid 图表在预览与详情页均正确渲染，且不溢出容器
- 编辑已完成文章后 URL 不变
- 局域网内其他设备访问不到本服务

## 9. 迭代路线

| 阶段 | 目标 |
|---|---|
| v0.1 | 本地写作闭环跑通（全部 P0） |
| v0.2 | 整理与检索：全文搜索、归档、深色模式、代码高亮 |
| v0.3 | 若决定公开：此时才引入鉴权、托管与域名 |

## 10. 成功标准

- 两周内作者本人写满 5 篇
- 其中至少 1 篇在断网环境下完成

功能清单打勾不算成功。个人写作工具唯一的真实风险是停更。
